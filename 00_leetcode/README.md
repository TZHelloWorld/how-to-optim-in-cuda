# LeetCode Hot100 入门与题解索引

以“读懂状态含义、解释每一步为什么正确”为目标，按 [LeetCode 热题 100 学习计划](https://leetcode.cn/studyplan/top-100-liked/)的 17 个分类整理 100 道题。

每道题包含题目链接、Python 实现、状态或函数含义、示例推演、易错点和复杂度。链表、二叉树、图另有基础知识与本地构造示例。

## 一、从哪里开始？

### 阶段 1：数组与字符串的基本方法

1. 哈希：理解用空间换查找效率。
2. 双指针、滑动窗口：理解指针移动为什么不会漏解。
3. 普通数组、矩阵：练习下标、边界、原地操作。
4. 子串、二分：学习前缀和、窗口极值、单调边界。

### 阶段 2：数据结构入门

1. 链表：节点身份、引用、dummy、反转、快慢指针。
2. 二叉树：DFS/BFS、递归返回值、BST、子树信息合并。
3. 栈、堆：后进先出、单调栈、Top K、双堆。
4. 图：邻接表、连通块、多源 BFS、拓扑排序、Trie。

### 阶段 3：搜索与最优化

1. 回溯：状态、选择、撤销、剪枝。
2. 贪心：局部决策为何能保留全局最优。
3. 动态规划：状态定义、最后一步分类、初始化、计算顺序。
4. 多维动态规划：网格、区间、两个字符串。
5. 技巧：异或、投票、分区、排列与隐式环。

不必按难度硬刷完整分类。比如先做链表反转再做 K 组反转，先学栈再做柱状图矩形，先理解一维 DP 再做最长有效括号。

## 三、如何使用代码？

- 每个题目代码块是一份独立实现。不同题都使用 `class Solution`，不要把多个代码块一起执行后再期待前面的类仍然存在。
- 链表和二叉树题，在线平台提供节点类型；本地运行需要先执行对应文档开头的节点定义。辅助构造函数用于练习，不需要提交到平台。
- `LRUCache`、`MinStack`、`Trie`、`MedianFinder` 按题目要求直接设计类，不包装成 `Solution`。
- 代码按原题输入约束编写；有些函数额外兼容空输入，但不能因此认为每个算法都适用于任意类型或非法参数。
- 原地题直接修改输入，返回值可能为 `None`；验证时检查修改后的对象。文档同时说明了排序、改链、网格标记等副作用。
- 复杂度默认采用常见整数操作模型，哈希操作按平均常数时间估计；辅助空间与输出空间尽量分开说明。

## 四、快速识别题型

| 问题特征 | 优先考虑 | 进一步确认 |
|---|---|---|
| 查找已出现的伙伴或频次 | 哈希 | 键应该保存什么？ |
| 连续区间，边界只向前 | 滑动窗口 | 合法性变化是否支持收缩规则？ |
| 区间和、包含负数 | 前缀和 + 哈希 | 是否统计历史前缀差？ |
| 有序范围、真假边界 | 二分 | 哪一半可以安全排除？ |
| 最近的更大/更小元素 | 单调栈 | 弹栈时能确定什么答案？ |
| Top K、动态极值 | 堆 | 需要淘汰最小还是最大？ |
| 枚举所有合法方案 | 回溯 | 状态如何恢复、怎样避免重复？ |
| 重复子问题、最优或计数 | DP | 状态是否足以决定后续问题？ |
| 无权最短步数、同时扩散 | BFS | 起点是一个还是多个？ |
| 有向依赖能否全部完成 | 拓扑排序 | 是否有环？ |

这些只是入口，不是看关键词套模板。例如“子数组”既可能用滑动窗口，也可能用前缀和、DP 或单调结构。

## 五、每题的学习方法

1. 不看代码，先用中文写出状态或函数的定义。
2. 用最小例子手算，画指针、递归树、队列或 DP 表。
3. 解释一次循环或一次递归会改变哪些信息。
4. 说明为什么不会漏解、重复计数或使用非法状态。
5. 检查空输入、单元素、重复值、负数、边界值是否属于原题范围，并测试相关情况。
6. 理解基础版本后再优化空间，不要为了短代码牺牲状态含义。
