# 基础知识

- GPU 的硬件执行模型：**Warp（线程束）** 是 GPU 执行的基本调度单位，由**32 个线程**组成。当一个 warp 执行一条访问全局内存的指令时，这 32 个线程各自产生的内存地址会被硬件**合并（coalesce）** 为尽可能少的**内存事务（memory transactions）**。


- 内存段（Memory Segment）：GPU 的设备内存（device memory，即 DRAM / HBM）不是逐字节随意访问的，而是通过固定大小的 **内存段（segment）** 来访问。每次内存事务操作的就是一个完整的段。

    - 内存段的三种粒度：32字节、64字节、128字节

        |        段大小|        对齐要求|        说明|
        |---|---|---|
        |        32 字节|        首地址必须是 32 字节的整数倍|        最小事务粒度|
        |        64 字节|        首地址必须是 64 字节的整数倍|        中间粒度|
        |        128 字节|        首地址必须是 128 字节的整数倍|        最大事务粒度/L1缓存行大小|

        > 这三种大小并非互斥，而是同一块 DRAM 的不同"视角"，硬件根据访问情况选择使用哪种粒度：这三个粒度（32 字节、64 字节、128 字节）**由 GPU 芯片的内存控制器物理总线宽度决定，是硬件固化的，程序员无法修改，也无法自定义其他值**（比如 48 字节或 96 字节的段）。
        > 
        > 
        > 
        > - "**起始地址必须是段大小的整数倍**" 这不是人为规定，而是**硬件寻址位运算的数学必然结果**。
        > 
        > - 编程的时候，访问数据时的数据指针可以是任意地址，不强制对齐内存段，但是合并成内存事务并由硬件执行时，只能以对齐的段为单位去读写 DRAM；
        > 
        > - 如果数据地址跨越了段边界，硬件会**自动拆成多个对齐事务**来覆盖整个数据范围
        > 
        > 

    - **自然对齐（naturally aligned）**的含义：一个 N 字节的段，其起始地址必须是 N 的整数倍。例如，一个 128 字节的段只能从地址 0、128、256、384... 开始。

    - 示例理解：假设有一块全局内存，地址从 0 开始：

        ```Bash
        0                    32                   64                   96                  128
        |----32B segment-----|----32B segment-----|----32B segment-----|----32B segment-----|
        |---------------64B segment---------------|---------------64B segment---------------|
        |-----------------------------------128B segment------------------------------------|
        ```

        每个事务只能读取/写入这些 **对齐边界上的完整段**，不能跨段合并，也不能只读取段的一部分（硬件层面总是传输完整段）。

        

使用 cudaMalloc 分配 GPU 内存。根据 [CUDA 文档](https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html#device-memory-accesses) 有：

>

- L2 缓存：**所有**全局内存访问都会经过 L2 缓存。L2 缓存是片上（on-chip）缓存，所有 SM（Streaming Multiprocessor）共享。L2 缓存的缓存行大小为**32 字节**。这就是为什么在现代 GPU（compute capability 6.0+）上，**全局内存访问的基本事务粒度是 32 字节**。


内存事务

- 一次 **内存事务（memory transaction）** 是 GPU 内存子系统执行的一次原子性的数据传输操作。它传输一个完整的、自然对齐的内存段。

- 事务粒度（Transaction Granularity）:一个 warp 的 32 个线程的内存访问，会被合并为所需的最少数量的 32 字节事务。

## 线程管理与启动(线程块和网格)


为了方便管理线程，将线程组织成块（线程块，Block），然后将线程块组织成网格（Grid）。线程块中的线程 和 网格中线程块 可以是 1 维、2 维或 3 维的。

必须明确，一个核函数只能有一个grid，一个grid可以有很多个块，每个块可以有很多个线程。

![image.png](images/image%206.png)

一个线程块内的所有线程都在同一个 SM 中执行，线程块内的所有线程都可以访问片上共享内存，用于在线程块内的线程之间交换信息。


线程块和线程块之间的调度无法保证，因此线程块不能依赖其他线程块的结果（**不同块内线程不能相互影响！他们是物理隔离的**）。CUDA 编程模型要求不同线程块中的线程之间不存在数据依赖关系。


### 编程如何区分每个线程？


由于每个线程都是执行同样的一串代码，那么就需要让每个线程能够相互进行区分，通过两个内置结构体确定线程标号：

- blockIdx（线程块在线程网格内的位置索引）

- threadIdx（线程在线程块内的位置索引）

这两个内置结构体基于 uint3 定义，包含三个无符号整数的结构，通过三个字段（x、y、z）来指定：

- blockIdx.x、blockIdx.y、blockIdx.z

- threadIdx.x、threadIdx.y、threadIdx.z


当然，我们需要用对应的两个结构体来保存对应的范围，即：

- blockDim

- gridDim

他们是dim3类型(基于uint3定义的数据结构)的变量，也包含三个字段（x、y、z）:

- blockDim.x、blockDim.y、blockDim.z

- gridDim.x、gridDim.y、gridDim.z

注意：dim3是手工定义的，主机端可见。uint3是设备端在执行的时候可见的，不可以在核函数运行时修改，初始化完成后uint3值就不变了。


如代码：

```C++
#include <cuda_runtime.h>
#include <stdio.h>

// Kernel definition
__global__ void checkIndex(void){
  printf("threadIdx:(%d,%d,%d) blockIdx:(%d,%d,%d) blockDim:(%d,%d,%d) gridDim(%d,%d,%d)\n",
      threadIdx.x,threadIdx.y,threadIdx.z,
      blockIdx.x,blockIdx.y,blockIdx.z,
      blockDim.x,blockDim.y,blockDim.z,
      gridDim.x,gridDim.y,gridDim.z);
}

int main(int argc,char **argv){
  
  dim3 grid(3,3);
  dim3 block(2,2);
  
  printf("grid.x %d grid.y %d grid.z %d\n",grid.x,grid.y,grid.z);
  printf("block.x %d block.y %d block.z %d\n",block.x,block.y,block.z);
  
  checkIndex<<<grid,block>>>(); // launch kernel
  cudaDeviceReset(); // cpu & gpu synchorize
  return 0;
}
C++
nvcc grid_block.cu -o grid_block
```

这里表示使用 $3 \times 3$ 的线程块网格启动，并且每个线程块中线程是 $2 \times 2$。（也就是启动这个内核，用了 $3 \times 3$ 个线程块， 每个线程块包含 $2 \times 2$ 个线程）。当然，启动核函数也可以使用 int 类型的变量（常亮）：

```C++
checkIndex<<<4, 8>>>();
```

如果一个warp其操作数之一或两者都还没有准备好（例如，尚未从全局内存中获取），就会发生一种称为“上下文切换”的过程，将控制权转移到另一个线程束上。但与CPU不同的是，在切换离开特定线程束时，该线程束的所有数据仍然保留在寄存器文件中，以便在其操作数准备好时能够快速恢复执行。所以线程束的切换是不需要开销的。

### 线程束（Warps） \& SIMT

在一个线程块内，线程被组织成32个线程一组的线程组，称为**线程束（warp）**。一个线程束以单指令多线程（SIMT，Single Instruction Multiple Thread）模式执行内核代码。在SIMT中，线程束内的所有线程都执行相同的内核代码，但每个线程可以执行不同的代码分支。基于此：

- 每个线程都有自己的指令地址计数器

- 每个线程都有自己的寄存器状态

- 每个线程可以有一个独立的执行路径

**对于硬件（SM）来说，CUDA执行的实质是线程束的执行，**即从机器的角度看，某个时刻T，SM上只执行一个线程束的指令。（同一时刻，一个SM最多只有32个线程（每个线程束一般是32个线程）在**同时同步**执行。线程块被分成多个线程束，并且将线程块中的线程束调度为**线程束流水线指令** 进行执行）

所以有个指标 **活跃线程束比例**，定义是：每个周期活跃的线程束的平均值与一个sm支持的线程束最大值的比。

### **CUDA编程的组件与逻辑**

注意：

- 一个线程是由 SM 中的一个 CUDA Core 执行。

- 一个线程块只能分配给一个 SM 执行（多个线程块可以分配到同一个SM上）,并且线程块中的所有线程（可能有多个线程束）共享其中的寄存器和共享内存。（SM中共享内存，和寄存器是关键的资源，其分配可能会严重影响性能）。

- SM有限，从编程角度看，所有的线程是并行执行的。但是从机器的微观角度看，线程块可能也是分批次在物理机器上执行的。

- SM执行指令的单位是线程束。线程块中的线程可能执行进度不一致。但是在同一个线程束中的线程拥有同样的进度。（并行就会有竞争，但是 CUDA 只提供了一种块内同步的方式），当某个线程块被分配到一个SM上的时候，会被分成多个线程束，线程束在SM上交替执行。

- 同一个SM上可以有不止一个常驻的线程束，有些在执行，有些在等待，他们之间状态的转换是不需要开销的。

## 全局内存

GPU 和 CPU 都有直连的 DRAM 芯片（多GPU系统中，每个GPU都有自己的DRAM内存；与GPU直连的DRAM被称为**全局内存**。与 CPU 直连的 DRAM 被称为**系统内存**或**主机内存**）。全局内存通过缓存实现加载和存储的过程如下图：

![image.png](images/image%2020.png)

核函数运行时需要从全局内存（DRAM）中**读取**数据，有两种粒度（最小单位）：

- 128 字节（启用一级缓存，一级缓存无法编程）

- 32 字节（通过编译指令 `-Xptxas -dlcm=cg`禁用一级缓存）


### 全局内存访问模式

- **对齐内存访问（Aligned Memory Access）**：当内存事务的第一个地址是缓存粒度(32字节的二级缓存或128字节的一级缓存)的偶数倍时就会出现对齐内存访问。运行非对齐的加载会造成带宽的浪费。

- **合并内存访问（Coalesced Memory Accesses）**：当一个线程束中全部的32个线程访问一个连续的内存块时，就会出现合并内存访问。

SM执行的基础是**线程束**，也就是说，当一个SM中正在被执行的某个线程需要访问内存，那么，**和它同线程束的其他31个线程也要访问全局内存。**


GPU**全局内存（Global Memory）**组织基于固定大小的**内存块（Memory Segment）** ，其划分依据与硬件缓存层次及内存控制器的设计密切相关。具体而言：

- 缓存行（Cache Line） ：GPU缓存（如L1、L2）以缓存行为最小数据管理单元。如，NVIDIA GPU的L1缓存行大小通常为128字节，L2缓存行大小为32字节。对于线程而言，**如果要读取全局内存，一定会经过 一级缓存/二级缓存 中的一个进行加载**。

- 内存控制器传输粒度 ：DRAM控制器的数据传输以固定大小的 **内存事务（Memory Transaction）**为基本单位，该单位通常与缓存行或其倍数对齐，直接影响数据存取效率。

基于此，是否对齐内存访问，就有：

- **未对齐访问（Unaligned Access）**：数据访问跨越内存事务边界（如32/128字节边界），需拆分为多个事务处理。

- **对齐访问（Aligned Access）**：数据访问严格限定于单个内存事务的边界内，无需拆分请求。


定义：从核函数发起的内存请求，到硬件响应返回数据这个过程称为一个**内存事务（Memory Transaction）。**其中，加载 和 存储 分别算一个内存事务。

如何理解？

事务合并的机制：合并是硬件自动进行的（同样，事务合并的支持性也由硬件决定），当访问模式满足条件时，就会生成更大的事务，而不是多次小事务。

硬件的事务合并能力取决于内存访问的对齐性 和线程束（Warp）访问模式 。以下是判断条件：

- 一段事务（32B） ：

    - 触发条件 ：线程束的访问地址无法合并为更大的段（如分散访问、未对齐到64B/128B边界）。

    - 示例 ：32个线程写入非连续的32B段（如每个线程写入不同段），需拆分为多个一段事务。

- 两段事务（64B） ：

    - 触发条件 ：线程束的访问地址在64B范围内连续且对齐到64B边界。

    - 示例 ：32个线程写入2个连续的32B段，合并为一个64B事务。

- 四段事务（128B） ：

    - 触发条件 ：线程束的访问地址在128B范围内连续且对齐到128B边界。

    - 示例 ：32个线程写入4个连续的32B段，合并为一个128B事务。

```C++
/* macro to index a 1D memory array with 2D indices in row-major order */
/* ld is the leading dimension, i.e. the number of columns in the matrix     */

#define INDX( row, col, ld ) ( ( (row) * (ld) ) + (col) )

/* CUDA kernel for naive matrix transpose */
__global__ void naive_cuda_transpose(int m, float *a, float *c )
{
    int myCol = blockDim.x * blockIdx.x + threadIdx.x;
    int myRow = blockDim.y * blockIdx.y + threadIdx.y;

    if( myRow < m && myCol < m )
    {
        c[INDX( myCol, myRow, m )] = a[INDX( myRow, myCol, m )];
    } /* end if */
    return;
} /* end naive_cuda_transpose */
```

### 共享内存访问模式

共享内存（shared memory， SMEM）是GPU的一个关键部件。物理上，每个SM都有 一个小的低延迟内存池，这个内存池被当前正在该SM上执行的线程块中的所有线程所共享。当每个线程块开始执行时，会分配给它一定数量的共享内存。 这个共享内存的地址空间被线程块中所有的线程共享。它和创建时所在的线程块具有相同生命周期。


共享内存被SM中的所有**常驻线程块**划分，是设备并行性的关键资源。一个**核函数**使用的共享内存越多，处于**并发活跃**状态的**线程块**就越少，因为虽然一个SM可以有多个活跃线程块，如果核函数占用的共享内存过多，就挤占了其线程块的资源，没有分配到共享内存资源的线程块就只有等待，从而减少了活跃线程块的数量。

从硬件层面看，一个SM一次只能计算一个block(中的一个warp)，但是可以常驻多个block???

SM在计算前就给各个block分配好了共享内存，常驻的块越多，分到每个块的共享内存就越少，分不够的时候，有些块就要等待别的块运算完才分配到，这种“等待”就表现为线程块的“不活跃”???


**存储体(banks)**：共享内存被划分成 32 个独立的 banks（对应线程束中32个线程），**每个 bank 具有独立的访问通道**。 共享内存是一个可以被**同时访问的一维地址空间**。 如果线程束32个线程通过共享内存32个 banks 加载或存储数据，且每个 bank 上只访问不多于一个的内存地址，则可由一个内存事务来完成。 否则，由多个内存事务来完成会降低内存带宽的利用率。


**存储体冲突 (Banks Conflicts)**：当同一个线程束 warps 中的多个线程尝试访问同一个数据块中的不同元素时，就会发生 Banks Conflicts。这种情况下，对该数据块中数据的访问将被串行化，直到所有请求该数据的线程都获取到数据为止。这种串行访问会导致性能损失。


一个线程束试图同时访问同一个 bank 中的 n 层数据将导致 n 次 内存事务(memory transaction)。亦称为 n 路 bank 冲突。


线程束共享内存请求模式：

- 并行访问： 多个地址访问多个存储体（不同线程访问不同的banks）

- 串行访问： 多个地址访问同一个存储体（不同线程访问同一个 banks 中的不同内存地址）

- 广播访问： 单一地址读取单一存储体 (a single address read in a single bank，不同线程访问同一个 banks 中相同的内存地址），线程束中所有的线程都读取同一存储体中相同的地址。若一个内存事务被执行，那么被访问的字就会被广播到所有请求的线程中。**广播访问无冲突**。


**存储体的宽度（Bank Width）**:存储体宽度（Bank Width）是并行计算中共享内存（Shared Memory）的物理特性。共享内存被划分为多个独立的存储体（Banks），每个存储体像一个小内存模块，拥有独立的读写通道，而每个存储体（Bank）一次能处理的数据位数或字节数就是存储体的宽度。
